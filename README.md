# OrchestrPay - проектирование платёжной платформы на Saga-оркестрации

Архитектурный проект платёжной платформы "OrchestrPay" (B2C и B2B) для обработки платежей
на маркетплейсах. Процесс спроектирован как оркестрируемая Saga на Camunda BPMN: списание
средств, антифрод-проверки, перевод контрагенту, автоматические компенсации и уведомления.
Проект состоит из 5 заданий, в каждом из которых решается отдельный архитектурный вопрос.

## Результаты по этапам

### 1. Проектируем шаги Saga

Анализ процесса и выделение всех транзакций Saga-оркестрации с классификацией по типу
(компенсируемая, необратимая, повторяемая) и указанием компенсирующих операций.

| Артефакт | Формат | Файл |
|----------|--------|------|
| Реестр транзакций Saga-оркестрации | Markdown | [saga-registry.md](Task1/saga-registry.md) |

### 2. Применяем State Machine на практике

"Таблица переходов", отражающая все возможные состояния платежа и события, которые
переводят его из одного состояния в другое, включая отказ антифрода, cut-off-таймеры,
ручную проверку и подтверждение операции.

| Артефакт | Формат | Файл |
|----------|--------|------|
| Таблица переходов состояний платежа | Markdown | [state-management.md](Task2/state-management.md) |

### 3. Решаем, где расположить оркестратор

ADR с описанием и сравнением двух вариантов размещения функции оркестрации - внутри
доменного сервиса (Payment Service) или в выделенном сервисе-оркестраторе.

| ADR | Тема | Артефакт |
|-----|------|----------|
| ADR-001 | Размещение функции оркестрации платежной Saga | [ADR.md](Task3/ADR.md) |

### 4. Формируем BPM-процесс

BPMN-диаграмма, отражающая весь процесс обработки платежа: успешные и компенсационные
развилки, шаг с ожиданием ответа после ручной антифрод-проверки, параллельные действия,
pivot-точка и автоматические возвраты.

| Диаграмма | BPMN | PNG |
|-----------|------|-----|
| Модель процесса обработки платежа | [payment.bpmn](Task4/payment.bpmn) | [payment.png](Task4/payment.png) |

### 5. Добиваемся качества реализации

Набор интеграционных и end-to-end тестов, покрывающих основной flow, corner cases и
сигнализирующих при возникновении ошибок.

| Артефакт | Формат | Файл |
|----------|--------|------|
| Таблица интеграционных и E2E тест-кейсов | Markdown | [tests.md](Task5/tests.md) |

## Как читать артефакты

Решение каждого задания содержится в отдельной директории `Task1`…`Task5`. Задания 1, 2 и 5
представлены таблицами в формате Markdown (реестр транзакций, переходы состояний, тест-кейсы).
Задание 3 оформлено как ADR с контекстом, рассмотренными вариантами, сравнением альтернатив и
принятым решением. Задание 4 содержит BPMN-модель процесса в исходном формате `.bpmn` и готовый
рендер `.png`.
